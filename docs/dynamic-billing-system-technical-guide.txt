1. SYSTEM OVERVIEW
==========================================

The Dynamic Billing System is a comprehensive healthcare billing automation platform
designed to process healthcare visits, organize them into billing batches, generate
insurance claims, and produce EDI (Electronic Data Interchange) files for submission
to insurance providers.

KEY FEATURES:
- Real-time visit filtering and processing
- Automated batch creation based on configurable time periods
- Intelligent claim grouping by tenant, service type, and provider
- X12 837P EDI file generation
- Complete audit trail and status tracking
- Multi-tenant architecture with company isolation
- HIPAA-compliant data handling

BUSINESS RULES:
- 15 minutes = 1 billing unit
- $17.17 per billing unit
- Visits must be approved before billing
- Same day visits for same tenant/HCM/service are grouped
- Different dates create separate LX segments in EDI

4. VISIT PROCESSING ENGINE
==========================================

VISIT ENHANCEMENT ALGORITHM:

STEP 1: TIME CALCULATION
```
INPUT: startTime, endTime
PROCESS:
  IF startTime AND endTime exist:
    timeInHours = (endTime - startTime) / (1000 * 60 * 60)
  ELSE:
    timeInHours = 1.0  // Default to 1 hour
  END IF
OUTPUT: timeInHours (rounded to 2 decimal places)
```

STEP 2: UNIT CALCULATION
```
INPUT: timeInHours
PROCESS:
  timeInMinutes = timeInHours * 60
  units = Math.max(1, Math.ceil(timeInMinutes / 15))
OUTPUT: units (minimum 1 unit)
```

STEP 3: AMOUNT CALCULATION
```
INPUT: units
PROCESS:
  ratePerUnit = 17.17
  calculatedAmount = units * ratePerUnit
OUTPUT: calculatedAmount (rounded to 2 decimal places)
```

EXAMPLE CALCULATIONS:

Visit 1: 30 minutes
- timeInHours = 0.5
- units = Math.ceil(30 / 15) = 2
- amount = 2 * $17.17 = $34.34

Visit 2: 90 minutes  
- timeInHours = 1.5
- units = Math.ceil(90 / 15) = 6
- amount = 6 * $17.17 = $103.02

Visit 3: 10 minutes
- timeInHours = 0.17
- units = Math.max(1, Math.ceil(10 / 15)) = 1
- amount = 1 * $17.17 = $17.17

VISIT STATUS LIFECYCLE:

not_scheduled ──schedule──▶ scheduled ──submit──▶ submitted ──bill──▶ billed
      │                        │                     │
      │                        │                     │
      └────────cancel──────────┼─────────cancel─────┘
                               │
                               ▼
                          cancelled

BUSINESS RULES:
- Cannot reschedule submitted or billed visits
- Cannot submit cancelled visits  
- Cannot cancel billed visits
- Can only bill submitted visits
- Cancelled and billed are final states

5. BATCH & CLAIM ORGANIZATION
==========================================

GROUPING STRATEGY:

PRIMARY GROUPING (Tenant + Service + HCM):
```
groupKey = tenantId + "_" + serviceType + "_" + hcmId
```

SECONDARY GROUPING (Date-based Sub-batching):
```
groupKey = tenantId + "_" + visitDate + "_" + hcmId + "_" + serviceType
```

TIME PERIOD CALCULATION:

```
FUNCTION calculateTimePeriod(startDate, endDate):
  IF no dates provided:
    RETURN 15  // Default 15 days
  
  daysDiff = (endDate - startDate) in days
  
  IF daysDiff <= 7:
    RETURN max(daysDiff, 7)  // At least 7 days
  ELSE IF daysDiff <= 15:
    RETURN 15
  ELSE IF daysDiff <= 30:
    RETURN 15  // Split into 15-day periods
  ELSE:
    RETURN 15  // Always use 15-day periods
  END IF
END FUNCTION
```

BATCH CREATION ALGORITHM:

```
FOR each tenant_service_hcm group:
  1. Sort visits by date chronologically
  2. Create date-based sub-batches:
     - Start new batch if visit date > (current_batch_start + time_period)
     - Add visit to current batch otherwise
  3. Generate unique batch ID: BATCH_{counter}_{year}_{month}_{counter}
  4. Generate unique claim ID: CLAIM_{counter}_{year}_{month}_{counter}
  5. Calculate totals: amount, units, visit count
  6. Set status based on visit statuses
  7. Update visits with batch and claim IDs
END FOR
```

EXAMPLE BATCH ORGANIZATION:

Input Visits:
- Visit A: 2025-01-15, Tenant1, HCM1, Housing Transition
- Visit B: 2025-01-16, Tenant1, HCM1, Housing Transition  
- Visit C: 2025-01-20, Tenant1, HCM2, Housing Transition
- Visit D: 2025-02-01, Tenant1, HCM1, Housing Transition

Output Batches:
- Batch 1: Visits A+B (same tenant, HCM, service, close dates)
- Batch 2: Visit C (different HCM)
- Batch 3: Visit D (different month, new period)

LX SEGMENT GENERATION LOGIC:

```
FUNCTION generateServiceLines(visitGroups):
  serviceLines = []
  lxCounter = 1
  
  // Sort groups by date, then HCM, then service
  sortedGroups = sort(visitGroups, [date, hcmName, serviceType])
  
  FOR each group in sortedGroups:
    serviceLine = {
      lxSequence: lxCounter++,
      serviceDate: group.visitDate,
      serviceType: group.serviceType,
      procedureCode: getProcedureCode(group.serviceType),
      lineItemChargeAmount: group.totalAmount,
      serviceUnitCount: group.totalUnits,
      hcmName: group.hcmId.name,
      visitCount: group.visits.length
    }
    serviceLines.push(serviceLine)
  END FOR
  
  RETURN serviceLines
END FUNCTION
```

7. STATUS MANAGEMENT
==========================================

STATUS TRANSITION VALIDATION:

```
FUNCTION validateStatusTransition(currentStatus, newAction):
  validTransitions = {
    'not_scheduled': ['schedule', 'cancel'],
    'scheduled': ['submit', 'cancel', 'schedule'],
    'submitted': ['bill', 'cancel'],
    'billed': [],
    'cancelled': []
  }
  
  IF newAction NOT IN validTransitions[currentStatus]:
    THROW "Invalid status transition"
  END IF
  
  RETURN true
END FUNCTION
```

STATUS UPDATE PROCESS:

```
FUNCTION updateVisitStatus(visitIds, action, additionalData):
  results = { successful: [], failed: [] }
  
  FOR each visitId:
    TRY:
      visit = findVisit(visitId)
      validateStatusTransition(visit.claimStatus, action)
      
      updateData = buildUpdateData(action, additionalData)
      updatedVisit = updateVisit(visitId, updateData)
      
      logAuditAction(visitId, action, updateData)
      results.successful.push(visitId)
      
    CATCH error:
      results.failed.push({visitId, error})
    END TRY
  END FOR
  
  RETURN results
END FUNCTION
```

DETAILED CALCULATION EXAMPLES:

SCENARIO 1: Standard Visit
- Start Time: 2:00 PM
- End Time: 3:30 PM
- Duration: 90 minutes

Calculation:
- timeInHours = 1.5
- units = Math.ceil(90 / 15) = 6 units
- amount = 6 × $17.17 = $103.02

SCENARIO 2: Short Visit
- Start Time: 10:00 AM  
- End Time: 10:10 AM
- Duration: 10 minutes

Calculation:
- timeInHours = 0.17
- units = Math.max(1, Math.ceil(10 / 15)) = 1 unit (minimum)
- amount = 1 × $17.17 = $17.17

SCENARIO 3: Extended Visit
- Start Time: 9:00 AM
- End Time: 1:00 PM  
- Duration: 240 minutes (4 hours)

Calculation:
- timeInHours = 4.0
- units = Math.ceil(240 / 15) = 16 units
- amount = 16 × $17.17 = $274.72

SCENARIO 4: Multiple Visits Same Day
Visit A: 30 minutes = 2 units = $34.34
Visit B: 45 minutes = 3 units = $51.51
Visit C: 60 minutes = 4 units = $68.68

Same Day Total:
- Combined units = 2 + 3 + 4 = 9 units
- Combined amount = $34.34 + $51.51 + $68.68 = $154.53
- EDI: Single LX segment with 9 units and $154.53

SCENARIO 5: Cross-Day Visits
Day 1: 60 minutes = 4 units = $68.68
Day 2: 90 minutes = 6 units = $103.02

EDI Output:
- LX*1 segment: 4 units, $68.68 (Day 1)
- LX*2 segment: 6 units, $103.02 (Day 2)

ROUNDING RULES:
- Time calculations: Round to 2 decimal places
- Unit calculations: Always round UP (ceiling)
- Amount calculations: Round to 2 decimal places
- Minimum billing: 1 unit (15 minutes)

ERROR HANDLING STRATEGY:

```javascript
function handleError(error, context) {
  // Log error with context
  logger.error('Error occurred', {
    error: error.message,
    stack: error.stack,
    context: context,
    timestamp: new Date(),
    requestId: context.requestId
  });
  
  // Determine error type and response
  if (error instanceof ValidationError) {
    return {
      success: false,
      code: 'VALIDATION_ERROR',
      message: error.message,
      details: error.details
    };
  }
  
  if (error instanceof BusinessError) {
    return {
      success: false,
      code: 'BUSINESS_ERROR', 
      message: error.message,
      details: error.details
    };
  }
  
  // Generic system error
  return {
    success: false,
    code: 'SYSTEM_ERROR',
    message: 'An unexpected error occurred',
    details: { requestId: context.requestId }
  };
}
```
